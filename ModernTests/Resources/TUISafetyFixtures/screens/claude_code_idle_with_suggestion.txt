⏺ I tested floating panes until I'd covered everything I could reach and found 23 bugs. Two are high severity; both lose data or
  leak running processes. I ran 121 tests across native floats, mouse and drag, persistence, the API and it2, tmux next-3.9 and
  Homebrew tmux 3.7c, multiple displays, and Metal rendering. Each bug has steps, expected and actual behavior, and screenshots
  or logs.

  High severity
  - BUG-18, tmux floats-only window: attaching (fresh or reattach) to a tmux window that has only floats makes iTerm2 send
    refresh-client -C @0:2x3. That crushes every float to 1x1 on the tmux server itself, so every client is affected, and the
    iTerm2 window shrinks to 26x95 pt. The debug log with the command is attached.
  - BUG-22, Undo Close of a window: the tiled panes come back as their original sessions, but the floats come back as brand-new
    shells, so their output and jobs are gone. The original float shells keep running with no UI: after two close-and-undo
    rounds there were four orphaned login processes. Undo Close of a tab also recreates its float as a new shell, but there the
    old process is killed.

  Medium severity
  - BUG-9: Duplicate Tab and Restore Window Arrangement add a row to every float, and it compounds with each round trip. A
    normal quit and relaunch keeps the sizes exactly.
  - BUG-10: after anything that briefly shrinks the tab, floats end up pinned to the bottom-right corner. Triggers include a
    window resize, Move Tab to New Window, toggling the Toolbelt, and a font change. In one case two floats ended up stacked
    exactly on top of each other.
  - BUG-12: at the 2x2 minimum size, typing a command makes zsh exit, so the float silently disappears.
  - BUG-15: Move Session to Split Pane started from a float can't be cancelled. The source float is hidden along with the
    others, so the cancel target never appears and Escape does nothing.
  - BUG-16: after swapping a float with a tiled pane, the new float keeps the tiled pane's full-height size instead of taking
    the old float's frame.
  - BUG-17: in tmux, a float created with new-pane -A while zoomed shows the wrong screen contents (the top lines are missing),
    and it stays wrong after unzoom.
  - BUG-7: dragging a float into another window lands it 35 pt too high when the source window has a tab bar.
  - BUG-1: a float pushed flush against the window's edge can't be resized from that edge; the drag resizes the window instead.

  The other 13 are lower severity: cursor and readout glitches, Lock Pane not stopping a float from moving, an API split of a
  float quietly splitting a tiled pane instead of failing, and a stale it2 binary in the Development build. Three of them
  (BUG-13, BUG-21 and part of BUG-23) are older problems that floats make easier to hit; the report says so for each. One lost
  window from the very first permission check didn't reproduce in two deliberate attempts, so it's listed as unreproduced.
